# HASP

HASP-ключ - аппаратное устройство, разработанное для предотвращения неконтролируемого копирования ПО. [1](https://www.securitylab.ru/blog/personal/xiaomite-journal/354608.php?ysclid=mhn36xboic802834181&utm_referrer=https%3A%2F%2Fya.ru%2F)

HASP содержит уникальный идентификатор (ID) и защищенную память, куда записываются данные, необходимые для работы определенного ПО.

## Эталонный алгоритм работы:
1. Пользователь запускает ПО
2. ПО проверяет наличие подключенного HASP-ключа
3. Если ключ обнаружен, ПО проверяет совпадение данных HASP с ожидаемыми
4. Если данные совпадают, то ПО продолжает работу
5. Если п.3 и п.4 не выполняются, то доступ блокируется

## ASIC

Базовая основа ключа HASP - заказная микросхема ASIC, имеющая уникальный для каждого HASP алгоритм работы. 

Что проверяет защищенное ПО подключенного к ПК HASP:
+ HASP возвращает правильные ответы
+ HASP работает по требуемому алгоритму
+ HASP обладает требуемыми эталонными характеристиками

В случае неуспеха реализуется реакция на НСД:
+ Запуск в демонстрационном режиме
+ Блокировка отдельных функций
+ Отказ в запуске
+ и т.д.

## HASP4 Standard

[3](https://studfile.net/preview/3619126/page:49/)

Основной элемент - аппаратно реализованная на ASIC микросхеме функция шифрования и связанная с ней функция отклика f(x), принимающая на вход 32-битный аргумент и формирующая на выходе четыре 32-битных значения.

Подходы к защите:
+ Проверка наличия HASP Standarad
+ Проверка соответствия выходов, формируемых функцией отклика f(x) для различных x, эталонным
+ Использовать функцию шифрования электронного ключа для шифрования и  дешифрования своего исполняемого кода, используемых данных и т.д.

## MemoHASP

Аналогичен HASP4 Standard, но обладает EEPROM (энергонезависимая память), доступная для чтения и записи во время выполнения защищенной программы.

Подходы к защите:
+ Хранение в EEPROM конфиденциальной информации - ключей шифрования, части исполняемого кода и т.д.
+ Хранение в EEPROM информации о модулях защищенного ПО, к которым пользователь имеет доступ и о тех, к которым не имеет (в зависимости от лицензии)
+ Хранение в EEPROM информации о количестве запусков ПО, либо об оставшемся количестве запусков. (для демо-версий ПО)

## TimeHASP

Аналогичен MemoHASP, но имеет также встроенные часы реального времени с автономным питанием от литиевой батарейки. Используя часы реального времени производитель может защищать свое ПО по времени использования.

## NetHASP

Аналогичен MemoHASP, но предназначен для защиты ПО в сетевых средах. Один ключ, установленный на любом компьютере сети, способен защитить ПО от тиражирования, а также ограничить количество рабочих мест (лицензий), на которых ПО используется одновременно. Ключ может работать на выделенном или невыделенном сервере, либо любой станции. Поддерживает различные протоколы - IPX/SPX, NetBIOS, NetBEUI, TCP/IP.

Управление ведется через менеджер лицензий.

## Схема взаимодействия с HASP-ключом

```
Серия           ---     Pass1, Pass2
ID              --->    Pass1, Pass2
F(x)            <--->   Pass1, Pass2
MEMO            <--->   Pass1, Pass2
TIME MEMO       <--->   Pass1, Pass2

Pass1, Pass2    <--->   Program
```

+ Серия - присваивается каждому из производителей защищаемого ПО, либо каждому ПО. Различные серии ключей HASP обладают различными функциями шифрования и различными кодами доступа. Серия не может быть программным путем прочитана, либо записана в HASP.
+ ID - номер, уникально идентифицирующий каждый из выпущенных HASP. Прошивается единожды в заводских условиях. Может быть прочитан программным путем.
+ F(x) - функция шифрования, реализованная аппаратно.
+ MEMO - энергонезависимая память для долговременного хранения конфиценциальной информации. Можно читать и писать.
+ TIME MEMO - энергонезависимая память для долговременного хранения информации, используемой TimeHASP при защите ПО по времени работы.
+ Таймер - используется для защиты ПО по времени своей работы. Ограничение по доступу к таймеру с помощью кодов доступа HASP не позволяет злоумышленнику несанкционированно использовать ПО путем корректировки таймера.

Способы внедрения защитных механизмов в ПО:
1. HASP API
2. HASP Envelope

Первый способ используется для встраивания защитных механизмов в исходные тексты. Сам код API функций защищен и зашифрован.

Второй способ служит для защиты исполняемых файлов. Исполняемый файл заключается в защитную программную оболочку, кодирующую файл, и обладающую такими свойствами, как распознавание ключа и антиотладка.

> Предпочтительно использование обоих способов одновременно.

## Система полного управления доступом в HASP (FAS)

FAS позволяет защищить несколько программ одним и тем же HASP-ключом. Возможно ограничение использования программ посредством:

+ Задания количества запуском программы
+ Задания допустимого срока работа программы
+ Задания числа станций, на которых программа может работать одновременно

В случае защиты с помощью подсистемы FAS, защищенное ПО осуществляет несколько проверок:

1. Проверяется, присоединен ли к компьютеру соответствующий ключ
2. Если ответ положительный, то память HASP проверяется на предмет того, занесена ли программа в список разрешенных к работе.
3. При положительном ответе выполняется серия проверок в зависимости от используемой модели HASP.

MemoHASP - проверяется превышение допустимого количества запуском программ. С каждым запуском число допустимых запусков уменьшается на 1.

HASP4 Time - опрашивается список допустимых сроков, результат сравнивается с реальным временем на таймере ключа.

## HASP API

Все функции HASP API (кроме NetHASP) вызываются через единую функцию hasp():

```
hasp(service, seed_code, lpt_num, pass1, pass2, par1, par2, par3, par4)
```

Для NetHASP:

```
hasp(service, seed_code, prog_num, pass1, pass2, par1, par2, par3, par4)
```

+ `service` - номер вызываемой функции (и соответствующей ей операции)
+ `lpt_num' - номер параллельного порта, к которому подключен HASP (0 - драйвер ищет автоматически)
+ 'seed_code' - значение, посылаемое в функцию отклика f(x)
+ `pass1`, `pass2` - пароль для HASP. Должен быть указан при доступе ко всем функциям, кроме функции проверки наличия HASP
+ `par1`, `par2`, `par3`, `par4` - параметры, через которые передаются значения в HASP и через которые возвращаются

## Система удаленного обновления (RUS)

RUS - утилита, позволяющая безопасно удаленно обновить содержимое ключей HASP у пользователя без необходимости раскрытия паролей.

## Модель защиты структурным кодом (PCS)

PCS - средство, повышающее защищенность ПО, защищаемого с помощью HASP. Реализуетя в процессе защиты с помощью HASP API. Использование PCS возможно лишь при наличии доступа к исходным текстам защищаемого ПО.

PCS осуществляет последовательность скрытых вызовов `hasp()`, не включая эти вызовы в исходный код явно. После каждого вызова `hasp()` происходит переключение на следующий скрытый вызов. Если вызов `hasp()` вдруг удален из защищенной программы, скрытый вызовы не выполняются, а это означает, что кто-то вмешался в работу программы. Тем семым PCS не дает удалить или "заклеить" обращение к процедуре `hasp()`.

Шаблон - специальная статическая структура данных, определенная в приложении. Включает в себя сигнатуру, номер функции `hasp()` и параметры, необходимые для работы данной функции.

Каждый вызов `hasp()` обновляет все шаблоны в коде, их после выхода из функции можно проверить.

Преимущества PCS:
+ скрывание обращения к HASP
+ трассировка вызовов `hasp()` для шаблонов практически невозможна
+ лег обнаруживается вмешательство извне
+ PCS препятствует эмуляции процедуры `hasp()`

## Рекомендации по наиболее надежной защите с помощью HASP

Существует два способа атаки на защищенное ПО:
+ заклеивание вызовов к защищающей приложение процедуре
+ заклеивание программы производителя ключа

Рекомендации:
+ Использовать одновременно методы защиты с помощью оболочки и с помощью API
+ Использовать больше вызовов `hasp()` и шаблонов PCS
+ Шифровать внутренние и внешние данные защищаемого приложения. Расшифрование проводить на HASP.
+ Избегать повторяющихся схем.
+ Разделять в коде программы шаги вызова процедуры `hasp()`, анализа ответных значений, возвращенных данной процедурой, и реакцию на результат анализа.
+ Использование функционирования программы в качестве ответа на отсутствие HASP.
+ Использовать HASP-зависимые данные. (например, хранить в EEPROM метку перехода, считывать ее и переходить по этой метке, а не сравнивать значения с эталонным напрямую)

> - Обфускация, динамическая криптография (часть алгоритма формируется на основе конкретного ключа и лицензии)?
> - Использование алгоритмов - AES, ECC (NIST, ГОСТ)?
> - Обеспечение целостности ПО - доверенная загрузка ПО ПАК?

## Концепт HASP

__Как ПО проверяет наличие подключенного HASP?__

Приложение работает с HASP-драйвером. Оно вызывает функцию из SDK (`hasp()`), библиотека связывается с системной службой, которая опрашивает подключенные USB-устройства. Если найден HASP, с которым прошла аутентификация (например, по challenge-response), то возвращается сессионный дескриптор. Приложение использует этот дескриптор для дальнейших операций.

__Как и какие данные ПО проверяет после обнаружения HASP?__

Приложение может:
1. Обратиться за данными, хранящимися в EEPROM HASP, которые представляют из себя метку перехода. Считать и перейти по этой метке в ПО.
2. Сгенерировать challenge, отправить его в HASP, тот вычислит reponse (по закрытому ключу, например), отправит его приложению, которому в свою очередь проверит reponse (с помощью открытого ключа, например)
3. Проверить метаданные ключа HASP, такие как серийный номер, тип устройства, наличие нужной опции, срок действия лицензии, версию прошивки, регион и т.п.
4. Расшифровать участки кода через HASP API и выполнить их в ПО
5. Проверить целостность ПО, DLL и т.п.
6. Держать открытую сессиию и периодически делать повторное шифрование, проверять метаданные, отслеживать таймауты и т.п.

__Как обеспечивается контроль лицензии?__

HASP хранит лицензию в EEPROM. Содержимое может быть зашифровано и недоступно напрямую. Изменения возможны только через RUS.

Примеры типов лицензии:
1. Перманентная - активна всегда, пока есть ключ
2. Демо-версия - есть счетчик запусков, уменьшается при каждом запуске ПО
3. Временная - есть timestamp, который проверяется по реальному времени
4. Сетевая - отслеживание количества одновременных логинов по сети и ограничение этого значения

Функции HASP:
+ Хранение лицензий и параметров
+ Криптооперации (challenge-response)
+ Контроль локальных счетчиков
+ Защищенное хранение секретов
- Не знает контекст приложения

Функции драйвера:
+ Обеспечивает связь с утройством
+ Управляет сессиями
+ Проверяет подписи и целостность лицензии
+ Отслеживает сроки и лимиты
+ Возвращает информацию приложению
- Не решает бизнес-логику приложения

Функции ПО:
+ Инициирует проверку
+ Проверяет возвращенные параметры
+ Управляет поведение ПО
+ Может выполнять дополнительные проверки
- Не может само проверить подпись лицензии

__Обеспечивается ли функциональность от заказчика?__

- Обеспечение доверенной загрузки ПО ПАК - Да (? за счет МДЗ или все же здесь имеется в виду проверка целостности ПО ?)
- Защита от копирования ПО  ПАК на идентичную аппаратную платформу - Да, за счет проверки HASP
- Размещение данных, необходимых для работы ПО, в защищенном хранилище - Да, в HASP есть EEPROM
- Периодическая проверка наличия USB-ключа - Да, ПО может вызывать нужную функцию и проверять HASP
- Извлечение данных из USB-ключа при старте ПО - Да, HASP может сохранять конфигурационные файлы в EEPROM и ПО сможет использовать драйвер и запросить эти файлы после проверки HASP
- Периодическое извлечение данных в ходе работы ПО - Да, ПО может обращаться к драйверу, который будет считывать нужные массивы данных
